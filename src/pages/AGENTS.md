# 页面范围

- 保持路由文件精简：加载/整理路由数据，选择正确的 `page` 标识符，将页面数据传入 `MainGridLayout`，并将呈现交给组件处理。在更改由配置驱动的页面行为前，请先阅读 `src/config/README.md`。
- 使用 `src/types/sidebarConfig.ts` 中已有的 `SidebarPage` 值；当引入一个真正全新的页面类别时，请同时更新类型、侧边栏过滤和针对性测试。将可见的路由文案保留在 i18n 中，而非硬编码字符串。
- 保留标题、描述、元数据和可访问名称的 SSR 输出。仅为无法在 SSR 中运行的行为添加 Svelte 水合（hydration）指令。在仅 SSR 的路由上，使用 `astro-icon` 渲染图标。
- `#swup-container` 之外的组件在导航过程中会持续存在。任何依赖于当前页面的横幅（Banner）、侧边栏、顶栏或其他外壳状态，都必须在 Swup 生命周期事件上保持同步，并在直接刷新和客户端导航两种情况下都经过测试。
- 保持 RSS、robots、sitemap 等端点路由为构建/服务端专用；不要在那里引入浏览器水合（hydration）。对于相册详情路由，在输出前对受保护的照片载荷进行加密，且绝不在 SSR HTML 中暴露明文受保护清单。
- 路由变更后，请运行针对性的页面片段以及 `tests/site/a11y.spec.ts`；当改动影响持久化外壳状态时，还应包含一条 Swup 导航断言。
