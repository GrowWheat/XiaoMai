# 国际化范围

- 每个新增的 `I18nKey` 必须在 `src/i18n/languages/` 下的全部十个语言模块中都有非空值。保持语言对象键与 `src/i18n/i18nKey.ts` 同步；类型检查能捕获缺失的键，但无法证明这些值是否有意义。
- 参数化的文案必须在各语言间保留完全一致的占位符名称集合，例如 `{date}` 或 `{days}`。在消费组件或页面中替换占位符；不要新增第二套临时翻译系统。
- 在新增受支持的语言或别名时，请更新 `src/i18n/translation.ts` 中的查找映射，并验证回退行为。保持现有的语言模块命名和导出的对象结构。
- 不要将路由特定数据、计数、日期或用户名放入语言文件。将这些值传入消费方的现有本地化模板，并在其对用户可见时测试替换路径。
- 对于 i18n 改动，请运行 `npx.cmd astro check` 以及渲染该新键的针对性页面/组件测试。当改动影响到对布局敏感的文案时，至少检查一个非默认语言。
