content-annotations把支撑性的上下文放在句子附近，又不把它直接放进阅读流中。点击小注释标记即可展开其内容。

## 基本语法

在普通正文中添加 `[+label]` 引用，然后在同一文章的其他位置定义对应的注释。

```markdown
Astro renders most of a page ahead of time and hydrates **interactive islands** [+islands] only when they need to become interactive.

[+islands]:
  An island is an interactive UI component surrounded by static HTML. This keeps the default page lightweight while preserving focused interactivity.
```

Astro 会预先渲染页面的大部分内容，并仅在**交互式孤岛** [+islands] 需要变为交互时才为其注水。

[+islands]:
  孤岛是被静态 HTML 包围的交互式 UI 组件。这让默认页面保持轻量，同时保留聚焦的交互能力。

## 富文本内容

定义中可以包含段落、强调、链接、列表和行内代码 [+rich-note]，而周围的句子照常继续。

[+rich-note]:
  **编写建议**

  - 让首句自成一体。
  - 当读者可能需要原始来源时，使用链接。
  - 优先使用简洁的示例，例如 `client:visible`。

  完整模型请参阅 [Astro 孤岛文档](https://docs.astro.build/en/concepts/islands/)。

## 多个定义

重复使用同一个标签 [+review]，在一个标记后呈现一组相关的简短注释。

[+review]: 从会改变读者下一步行动的决策开始。
[+review]: 将实现证据与背景上下文分开。
[+review]: 删除那些本应属于正文而非注释的细节。

诸如 `[+missing]` 之类的未定义引用会保持为普通文本，因此未完成的注释永远不会产生一个空控件。
